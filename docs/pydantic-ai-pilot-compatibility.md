# Pydantic AI skill-driver compatibility

This matrix describes the opt-in `capability_pilot` as it exists in this
checkout. It is a bounded research driver, not a replacement for JV Agent's
legacy Orchestrator. Passing a source-level or unit-test gate does not qualify
a provider or integration for production use.

| Surface | Current contract | Qualification |
|---|---|---|
| Skill authoring | Uses existing JV `SKILL.md`; only the `research` skill with `spec: jv`, an `evidence_required` output contract, the exact declared search/fetch tool set, and no task-lock/flow requirements is admitted. | Supported for this fixed research skill by admission code and skill/runtime tests. Arbitrary skills and interview/task-lock flows are rejected. [admission](../jvagent/action/orchestrator/orchestrator_interact_action.py:1558), [pilot runtime](../jvagent/action/orchestrator/pilot/runtime.py:897) |
| Output | Fresh runs return `ResearchBrief`. Findings cite host-observed successful fetch receipts and must include quote anchors; citations are rendered by the host. | Structural contract tested. Quote matching does not prove semantic entailment or truth; blind quality evaluation remains open. [contracts](../jvagent/action/orchestrator/pilot/contracts.py:204), [progress evidence](../.planning/reviews/2026-10-05-enterprise-harness-goal-progress.md:31) |
| Action plugins | The pilot requires host-qualified Serper search and WebFetch evidence tools, and may compose additional tools explicitly declared by the skill when each Action tool declares `effect_class="read"`. Each call validates the Action schema, checks current AccessControl, and rejects authority-bearing arguments. | Read classification is a reviewed Action contract, not proof of side-effect freedom. Extra Action output does not become citation evidence unless the host evidence collector recognizes it. Write/external, MCP, visitor-bound, and flow tools remain excluded. [admission](../jvagent/action/orchestrator/orchestrator_interact_action.py:1588), [tool admission](../jvagent/action/orchestrator/pilot/tools.py:174), [action authoring](../.planning/reference/action-authoring.md:405) |
| Model Actions | The configured JV model Action must implement `complete()`; streaming-capable Actions additionally use `query_messages(stream=True)`. Provider-specific Pydantic settings require a `pydantic_ai_supported_settings` declaration and matching wire mapping. | OpenAI/Ollama payload mappings have deterministic tests. A configured Ollama Cloud browser call returned 401, so successful provider behavior, usage, and billing are not qualified. [adapter](../jvagent/action/orchestrator/pilot/runtime.py:536), [provider settings](language-models.md#pydantic-ai-skill-driver-model-settings), [Phase 61](../.planning/reviews/2026-10-05-enterprise-harness-goal-progress.md:941) |
| LiteLLM | Provider-specific settings are rejected while `drop_params` is enabled; set it to `false` to avoid silent parameter removal and let the provider reject unsupported fields. | Parameter forwarding is source-tested; no successful live provider call is qualified. [LiteLLM Action](../jvagent/action/model/language/litellm/litellm_lm.py:39) |
| MCP and visitor-bound tools | MCP Actions, InteractActions, and tools bound to a visitor are excluded from the pilot tool surface. | Unsupported by design; these integration classes have no pilot conformance claim. [tool collection](../jvagent/action/orchestrator/orchestrator_interact_action.py:1586) |
| Interviews and multi-step task flows | Skills with `task_lock` or `requires_tasks` are rejected. | Unsupported by design; no interview continuation or task-flow replay is implied. [admission](../jvagent/action/orchestrator/orchestrator_interact_action.py:1571) |
| Delegation and subagents | The pilot constructs one Pydantic AI Agent for one admitted skill and exposes only that skill's declared Actions. It has no delegate/subagent tool. | Unsupported by design; delegation, nested agents, and multi-agent write boundaries are unqualified. [Agent construction](../jvagent/action/orchestrator/pilot/runtime.py:952) |
| Writes and external effects | The admitted research surface is read-only search/fetch. No write Action is reachable through the fixed tool allowlist. | Unsupported by design. Do not infer that graph-backed task writes authorize business-side effects. [admission](../jvagent/action/orchestrator/orchestrator_interact_action.py:1576) |
| Identity and access | Caller identity is established from the server's `InteractWalker`; every Action invocation rechecks `AccessControl`. Signed host context is separately bound to caller/run identity and replay controls. | Source and graph regressions cover these boundaries; distributed multi-worker qualification remains open. [caller binding](../jvagent/action/orchestrator/orchestrator_interact_action.py:1627), [tool access](../jvagent/action/orchestrator/pilot/tools.py:252) |
| State and recovery | Pilot snapshots, usage counters, evidence, delivery attempts, and acknowledgments use the existing graph-backed `TaskStore`; interrupted active runs fail closed and require an explicit fresh request. | Graph tests cover persistence and recovery boundaries. Exact Pydantic message replay, multi-worker lease fencing, and lifetime settlement across all restart paths remain incomplete. [TaskStore](../jvagent/action/orchestrator/pilot/state.py:25), [recovery record](../.planning/reviews/2026-10-05-enterprise-harness-goal-progress.md:324) |
| Egress and UI | Final output uses the configured `ReplyAction` and existing response bus. Tool/reasoning events use the existing Messenger protocol; final structured output is withheld until validation. | Event and delivery-state tests exist. Browser evidence is currently a bounded 401 failure; successful streamed research and remote delivery acknowledgment are unqualified. [publication path](../jvagent/action/orchestrator/orchestrator_interact_action.py:2085), [tool events](../jvagent/action/orchestrator/orchestrator_interact_action.py:1877) |
| Run policy | Tool timeout comes from `tool_call_timeout` (channel override supported); concurrency uses the Orchestrator's bounded configuration, with a maximum of eight. | Deterministic mapping/validation tests pass. Concurrency with a production shared graph backend still needs deployment qualification. [policy mapping](../jvagent/action/orchestrator/orchestrator_interact_action.py:2035), [Agent policy](../jvagent/action/orchestrator/pilot/runtime.py:934) |

## Expansion gate

Add an integration class only after it has a named contract, an adversarial
regression for its authority and failure boundaries, a provider/deployment
conformance result, and a real browser flow with persisted graph readback. The
current matrix intentionally leaves MCP, interviews, delegation, writes, and
unqualified providers outside the pilot. See the [enterprise harness
acceptance record](../.planning/reviews/2026-10-05-enterprise-harness-goal-progress.md)
for tested revisions, browser outcomes, and open qualification limits.
